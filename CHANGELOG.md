# История изменений

Описание каждой версии — то, что изменилось после предыдущей. В конце каждого пункта указан
запрос на слияние (или коммит, если запроса не было), в котором сделано изменение. Формат описан
в `.github/RELEASE_TEMPLATE.md`; раздел версии становится описанием её выпуска на GitHub.

## 4.0.0-rc.2

Повреждённые файлы данных: программа исправляет что может сама, называет файл и раздел, когда
не может, и предлагает вернуть файл из своей копии. Копий теперь три, за последние двое суток.
Несколько torrent-клиентов: у каждой темы свой клиент, один из клиентов основной.

### ⬆️ Что нужно сделать

- Задать torrent-клиент заново в **Настройки → Torrent-клиенты**: в 4.0.0-rc.1 и бета-версиях
  он был один и хранился иначе, эти настройки не переносятся. Пока клиента нет, torrent-файлы
  только сохраняются. Темы, трекеры и остальные настройки остаются как есть.
- Если используется Sonarr и раздачи идут не в основной клиент, назвать клиент в адресе webhook:
  `…&client=НАЗВАНИЕ`.

### ✨ Новое

- Несколько torrent-клиентов — сколько угодно, в том числе одного вида на разных серверах.
  Один клиент основной: ему достаются темы без своего клиента, темы из REST API и из Sonarr.
  У темы клиент выбирается в её форме и показан в списке «Торренты»; тему можно перенести
  в другой клиент. REST API принимает `client`, webhook Sonarr — `&client=`. Клиент, который
  не отвечает, не задерживает остальные.
  См. [Несколько клиентов](https://github.com/azinchen/TorrentMonitor/wiki/Torrent-Clients#несколько-клиентов) (#45)

- Кнопка **Восстановить из копии** на странице «TorrentMonitor не может начать работу»: когда
  файл данных повреждён и у программы есть его предыдущая версия, она возвращается на место,
  а повреждённый файл сохраняется рядом.
  См. [Решение проблем](https://github.com/azinchen/TorrentMonitor/wiki/Troubleshooting#torrentmonitor-не-может-начать-работу) (#44)
- Копий файла настроек и файла тем теперь три: перед последним сохранением, примерно суточной
  и двухсуточной давности. В **Состояние → Копии данных** любой из них можно вернуть файл —
  например, если темы удалены по ошибке.
  См. [Копии файлов данных](https://github.com/azinchen/TorrentMonitor/wiki/Troubleshooting#копии-файлов-данных) (#44)
- Повреждённый `state.json` не останавливает программу: он откладывается, начинается новый,
  и это записывается в журнал (#44)
- Неожиданная ошибка программы показана одним предложением и записана в журнал, а не выводится
  текстом PHP с путями сервера. Проверка по расписанию при такой ошибке завершается
  с сообщением, а не молча (#44)

### 🐛 Исправлено

- Файл данных, который читается, но устроен неверно (у темы нет номера, вместо текста список,
  запись темы пуста), приводил к ошибке PHP вместо интерфейса, а проверка по расписанию
  переставала работать. Теперь значения с очевидным содержимым исправляются сами, а если
  раздел настроек или тем не угадать, программа называет файл и раздел (#44)
- Если `config.json` пропал, а темы остались, первоначальная настройка больше не предлагается:
  раньше пароль мог задать любой, кто открыл адрес (#44)
- `config.json` без раздела настроек оставлял интерфейс закрытым паролем, которого нет (#44)


## 4.0.0-rc.1

Кандидат в выпуск 4.0.0. Программа переписана: данные хранятся в файлах, а не в базе, новый
веб-интерфейс, журнал событий, состояние раздач из torrent-клиента. Здесь описано всё, что
изменилось после версий 3.x; от 4.0.0-beta11 эта версия отличается только номером.

### ⬆️ Что нужно сделать

- С бета-версии 4.0 — ничего.
- С версии 3.x или 2.x: перенести данные из базы — `php tools/convert-db.php`, один раз
  (в Docker контейнер делает это сам при первом запуске) — и направить веб-сервер на каталог
  `public/`. Порядок перехода — в вики, на странице
  [Обновление](https://github.com/azinchen/TorrentMonitor/wiki/Updating#переход-с-версии-3x).
- Нужен PHP 8.0 или новее. База данных больше не нужна. Расширение iconv больше не нужно
  (хватает mbstring), поэтому на Alpine не требуется собирать GNU libiconv.

### Хранение данных

- Настройки, темы и состояние лежат в JSON-файлах в каталоге данных. MySQL, PostgreSQL и SQLite
  не используются (#3)
- Программа, настройки и данные недоступны из браузера: корень сайта — каталог `public/` (#3)
- Файлы данных, их копии и журналы доступны только пользователю программы (и группе, если каталог
  данных настроен для двух пользователей). Настройка **Права на файлы данных** открывает их
  другим пользователям сервера.
  См. [Настройки](https://github.com/azinchen/TorrentMonitor/wiki/Settings#права-на-файлы-данных) (#3, #10, #17, #40)
- Файлы данных подходят любой версии программы: новая версия только добавляет поля, прежняя
  сохраняет то, чего не знает. После возврата на предыдущую версию данные остаются рабочими (#4)
- Перенос данных прежней версии работает с базами версии 2.0 и новее и сообщает, какую версию
  базы нашёл. Трекеры, переименованные с тех пор, переносятся под нынешним названием, а темы
  трекеров, с которыми версия 4 не работает, перечислены в отчёте (#3, #39)

### Трекеры

- Трекеры за Cloudflare работают и с FlareSolverr, и с Byparr: вход, страницы тем и скачивание
  torrent-файлов (#3)
- У трекера можно указать другой адрес (зеркало); у LostFilm есть запасные адреса (#3)
- Вход по cookie из браузера для трекеров, которые требуют капчу (#3)
- Кнопка «Удалить учётные данные» у трекера: убирает логин, пароль и сохранённую сессию (#3)
- nnmclub.to работает без учётной записи: темы проверяются без входа, как их видит гость.
  Учётную запись по-прежнему можно задать — тогда скачанное учитывается в рейтинге (#33)
- «Сохранить и проверить» у трекера, который используется без входа, открывает трекер
  и сообщает, отвечает ли он (#34)
- Настройка **Часовой пояс трекеров** (по умолчанию московский); у трекера может быть свой.
  См. [Настройки](https://github.com/azinchen/TorrentMonitor/wiki/Settings#время-и-часовые-пояса) (#15)
- kinozal.me и anidub.com: слова «сегодня» и «вчера» считались по часам сервера, поэтому
  на сервере не в московском поясе раздача могла скачаться повторно (#15)
- kinozal: если адрес записи не отвечает, пробуются другие адреса трекера. Домен kinozal.tv больше
  не работает, темы под этой записью проверяются через kinozal.me и kinozal.guru (#3)
- nnmclub.to и booktracker.org: дата раздачи находится и при изменённой разметке страницы;
  booktracker.org берёт cookie сессии `bb_data` (#3)
- riperam.org и rustorka.com открываются по https; собственная капча rustorka.com при входе
  распознаётся и объясняется в ошибке (#3)
- Убраны casstudio.tk, hamsterstudio.org, tfile.cc и baibako.tv: эти сайты больше не отвечают (#3)

### Проверка

- Проверка загружает страницы тем частями по сто и сохраняет найденное один раз на часть.
  При нескольких тысячах тем она идёт в разы быстрее, а памяти нужно столько же, сколько при
  сотне тем (#22)
- Трекеры опрашиваются одновременно, до трёх сразу; предел одновременных запросов считается
  на каждый трекер. Расширенные настройки **Запросов к одному трекеру** и **Трекеров
  одновременно** (#22)
- Два запуска одновременно не работают; без интернета трекеры не опрашиваются (#3)
- Когда трекер не отвечает, в ошибке сказано, в чём дело: не отвечает прокси или сам трекер
  (адрес не найден, нет ответа, отказ в соединении, ошибка TLS) (#3)
- Тему, которая давно не обновлялась, можно перестать проверять автоматически (#3)
- `php engine.php --tracker=…`, `--topic=…`, `--dry-run` (#3)

### Torrent-клиенты

- Состояние раздачи в torrent-клиенте у каждой темы на странице «Торренты»: загружается
  (с процентом), раздаётся, остановлена, в очереди, проверяется, ошибка, нет в клиенте.
  Работает с qBittorrent, Transmission и Deluge. Если клиент не отвечает, об этом сказано
  одной строкой над списком.
  См. [Торренты](https://github.com/azinchen/TorrentMonitor/wiki/Web-Interface#торренты) (#41)
- qBittorrent, Transmission и Deluge получают torrent-файл напрямую, без ссылки на TorrentMonitor (#3)
- При удалении темы можно удалить раздачу и скачанные файлы (#3)
- qBittorrent: если он сбросил сеанс (так бывает, когда рядом работает Sonarr), вход повторяется (#7)
- Synology Download Station: номер задачи определяется только по ссылке раздачи, чужая задача
  больше не может быть удалена при обновлении (#3)

### Sonarr

- Webhook отвечает сразу, работает с qBittorrent, Transmission и Deluge, сохраняет каталог и
  категорию раздачи, не считает ошибкой уже отслеживаемую тему и остальные события (#3)
- Тему, добавленную вручную, можно связать с сериалом Sonarr (название сериала и сезон): тогда она
  заменяется и удаляется вместе с сериалом так же, как темы, добавленные Sonarr.
  См. [Интеграция с Sonarr](https://github.com/azinchen/TorrentMonitor/wiki/Sonarr-Integration#связь-своей-темы-с-сериалом) (#6)
- По желанию удаляет темы сериала, когда сериал удалён в Sonarr (#3)
- По желанию удаляет прежнюю тему сезона (и отдельной настройкой — её раздачу), когда Sonarr
  загружает этот сезон целиком другой раздачей (#3)
- Раздача, названная по сезону без номера серии, считается сезоном целиком (#7)
- Раздачи с nnmclub.to берутся на мониторинг: трекер записывает в torrent-файл адрес сообщения,
  а не темы, и тема находится по нему. Такую ссылку можно и вставить при добавлении темы (#34)

### Веб-интерфейс

- Новый интерфейс: Торренты, Пользователи, Трекеры, Настройки, Состояние, Журнал. Светлая
  и тёмная темы, работает на телефоне, не загружает файлы с других сайтов (#3, #40)
- Первоначальная настройка при первом запуске; пароля по умолчанию больше нет (#3)
- Список тем: отметка **Компактно** (каждая тема одной строкой), выбор порядка — по дате
  обновления, названию, дате добавления, трекеру, состоянию в клиенте, сначала с ошибками —
  и показ страницами по 50, 100 или 200 записей (#11, #25, #41)
- Время показано по часам браузера, а дата раздачи — ещё и по часам трекера (#15, #20)
- Все трекеры на одной странице, с проверкой входа (#3)
- Кнопки **Сохранить и проверить**: подключение к torrent-клиенту, сеть (выход в интернет
  и решатель Cloudflare) и уведомления — с ответом самого сервиса при отказе.
  См. [Уведомления](https://github.com/azinchen/TorrentMonitor/wiki/Notifications#проверка) (#3, #24, #29)
- Настройки, которые обычно менять не нужно, скрыты: их показывает отметка **Показать
  расширенные** вверху страницы «Настройки» (#22, #24)
- «Проверка работы» на странице «Состояние» и кнопка **Скопировать сведения**: версии
  и настройки без паролей для сообщения об ошибке (#3, #26)

### Журнал

- Страница «Журнал» — всё, что происходило, одним списком на всю высоту окна: проверки
  с итогом и названиями обновлённых тем, ошибки, обновления программы, изменения настроек
  и трекеров, добавленные, удалённые и переименованные темы, неверные пароли при входе.
  Есть поиск, выбор вида событий и кнопка «Скачать», которая сохраняет то, что показано.
  См. [Журнал](https://github.com/azinchen/TorrentMonitor/wiki/Web-Interface#журнал) (#26, #31, #32, #40)
- Ошибка записывается в журнал, когда она появилась, а не при каждой проверке, пока она длится.
  Отметки ошибок у тем и трекеров остались (#35)
- **Подробный журнал проверки**: каждая проверенная тема и каждый запрос, со сведениями
  о программе, torrent-клиенте и решателе Cloudflare. Включается на странице «Журнал», строки
  проверок показаны между событиями; хранятся журналы нескольких последних проверок.
  См. [Журналы](https://github.com/azinchen/TorrentMonitor/wiki/Troubleshooting#журналы) (#26, #36, #40)
- **Скрыть личные данные**: адреса ваших сервисов, каталоги, имена пользователей трекеров
  и IP-адреса заменяются на «адрес 1», «каталог 1» — на экране, в скачанном файле и в тексте
  «Скопировать сведения». Пароли и ключи в журнал не пишутся никогда (#40)
- Журнал отмечает смену версии, которую выполнил не сам TorrentMonitor, — новый образ Docker
  или замена файлов вручную (#31)

### Уведомления

- Уведомление об обновлении раздачи показывает дату по часам сервера и, если они отличаются,
  по часам трекера: «23 ноя 2026, 06:23 (на трекере 14:23 МСК)» (#20)
- Pushall: неверный ключ считался успешной отправкой; Telegram: адрес без номера чата считался
  рабочим, хотя сообщение никому не отправлялось (#29)

### Обновления

- Новые версии берутся из GitHub Releases этого репозитория. Обновление удаляет файлы прежней версии (#3)
- Автоматическая установка может следовать за стабильными версиями, бета-версиями или версией
  в разработке. При смене выбора устанавливается последняя версия нового выбора, даже если она
  ниже установленной.
  См. [Обновление](https://github.com/azinchen/TorrentMonitor/wiki/Updating#какие-версии-устанавливаются) (#16)
- Блок обновлений в «Настройки → Общие»: установленная версия, кнопки «Проверить обновления»
  и «Установить». Проверка, запущенная кнопкой «Проверить сейчас», спрашивает о новой версии
  сразу (#23, #40)
- Описание новой версии показано с заголовками, списками и ссылками на изменения. Если
  пропущено несколько версий, показаны описания всех. Раздела «Новости» больше нет (#13, #18, #19)

### API

- Имена полей темы изменены: `torrent_id` → `topicId`, `hd` (`0`, `1`, `2`) → `quality`
  (`sd`, `720`, `1080`), `ep` → `episode`, `timestamp` → `updatedAt`, `auto_update` → `autoRename`,
  `pause` → `paused`. Логические значения стали настоящими `true`/`false` (были `0`/`1`) (#3)
- Новые поля темы: `url`, `stopAfterDays`, `addedAt`, `lastActivityAt`, `stopped`, `updatedAtUtc`
  (дата раздачи в UTC). Список и одна тема возвращают одинаковый набор полей (#3, #15)
- В `GET /api/errors` поля переименованы: `reason` → `code`, `tracker` → `source`, `id` → `topic` (#3)

### Лицензия

- MIT. Сторонняя библиотека Transmission под GPL заменена собственным кодом (#3)


## 4.0.0-beta11

Состояние раздач из torrent-клиента в списке тем; страница «Журнал» с поиском, скачиванием и скрытием
личных данных; перенос данных из баз версии 2.0 и новее.

### ✨ Новое

- Состояние раздачи в torrent-клиенте у каждой темы на странице «Торренты»: загружается
  (с процентом), раздаётся, остановлена, в очереди, проверяется, ошибка, нет в клиенте.
  Работает с qBittorrent, Transmission и Deluge. Если клиент не отвечает, об этом сказано
  одной строкой над списком.
  См. [Торренты](https://github.com/azinchen/TorrentMonitor/wiki/Web-Interface#торренты) (#41)

  в клиенте (#41)

### 🐛 Исправлено

- Файлы подробного журнала проверки (`engine*.log`) создавались доступными для чтения всем
  пользователям сервера. Теперь у них те же права, что у файлов данных, и настройка «Права
  на файлы данных» действует и на журналы (#40)

### ♻️ Изменено

- Адреса torrent-клиента, решателя Cloudflare, прокси и самого TorrentMonitor снова пишутся

### ⬆️ Что нужно сделать

- Файлы данных доступны только пользователю программы (и группе, если каталог данных настроен
  для двух пользователей) (#3)
