# Прокси и зеркала

Трекеры часто блокируются провайдерами. TorrentMonitor предлагает несколько
инструментов обхода: глобальный прокси, индивидуальные прокси для конкретных
трекеров, другой адрес (зеркало) трекера и FlareSolverr/Byparr против Cloudflare.

---

## Глобальный прокси

**Настройки → Прокси** → «Использовать прокси»:

- **Тип прокси** — HTTP или SOCKS5;
- **IP и порт** — например `127.0.0.1:9050` (стандартный порт TOR).

Через глобальный прокси идут **все** запросы TorrentMonitor к трекерам.

## Прокси только для одного трекера

Задаётся в **Настройки → Расширенные**, в поле «Прокси для отдельных трекеров»,
в виде JSON:

```json
{
    "lostfilm.tv": { "use": "yes", "type": "SOCKS5", "address": "192.168.1.220:8118" },
    "rutracker.org": { "use": "no" }
}
```

- `use` — `"yes"`: ходить на этот трекер через прокси; `"no"`: всегда напрямую,
  даже если включён глобальный прокси;
- `type` — `HTTP` или `SOCKS5`;
- `address` — IP:порт прокси. Если не указан, используется глобальный прокси
  из вкладки «Прокси».

Настройка для трекера важнее глобального прокси. Пустое поле — индивидуальных
прокси нет.

## Другой адрес трекера (зеркало)

В разделе **Учётные данные** у каждого трекера, которому нужна учётная запись,
есть необязательное поле **Адрес** — другой адрес (зеркало) этого трекера:

```
https://rutracker.net
```

- Можно указать несколько адресов через запятую — используется первый доступный.
- Ссылки на темы с адресом зеркала распознаются при добавлении темы.
- У lostfilm.tv запасные адреса встроены: www.lostfilm.download, затем
  www.lostfilm.tv, затем www.lostfilmtv5.site.

Некоторые другие адреса трекеров распознаются при добавлении темы без настройки:

| Адрес в ссылке | Трекер |
|---|---|
| rutracker.net, rutracker.nl | rutracker.org |
| nnm-club.me | nnmclub.to |
| tr.anidub.com | anidub.com |
| rutor.info | rutor.is |

kinozal.tv, kinozal.me и kinozal.guru — три отдельные записи в списке трекеров,
у каждой свои учётные данные.

## TOR

Классическая связка для доступа к заблокированным трекерам — TOR как SOCKS5-прокси:

1. Установите TOR (пакет `tor`; в Docker — отдельный контейнер).
2. Убедитесь, что SOCKS-порт 9050 доступен для TorrentMonitor.
3. Укажите в TM прокси SOCKS5 `127.0.0.1:9050` (или адрес контейнера TOR).

Готовый рецепт для Docker (TOR + Transmission + TM в одной связке) описан в вики
Docker-проекта: [TOR-and-Transmission](https://github.com/alfonder/torrentmonitor-dockerized/wiki/TOR-and-Transmission).

Учтите, что через TOR трекеры отвечают заметно медленнее — при таймаутах
увеличьте «Таймаут HTTP-запросов» в **Настройки → Расширенные**.

## Cloudflare: FlareSolverr и Byparr

Некоторые трекеры закрыты проверкой Cloudflare, которая не пропускает автоматические
запросы. Её проходит решатель — [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr)
или [Byparr](https://github.com/ThePhaseless/Byparr): он открывает страницу в настоящем
браузере. Оба подключаются одинаково, одной настройкой.

1. Запустите решатель — обычно это Docker-контейнер, порт 8191. FlareSolverr:

   ```yaml
   services:
     flaresolverr:
       image: ghcr.io/flaresolverr/flaresolverr:latest
       container_name: flaresolverr
       restart: unless-stopped
       ports:
         - "8191:8191"
   ```

   Byparr — так же, с образом `ghcr.io/thephaseless/byparr:latest`.

2. В TM: **Настройки → Расширенные → FlareSolverr URL** →
   `http://flaresolverr:8191` (или `http://byparr:8191`, `http://127.0.0.1:8191`).

Если поле пустое, проверка Cloudflare не проходится.

### Как это работает

1. Трекер отвечает проверкой Cloudflare.
2. TorrentMonitor просит решатель открыть этот адрес в его браузере.
3. Cookie прохождения проверки и User-Agent браузера сохраняются для этого сайта.
4. TorrentMonitor повторяет запрос напрямую, с этими cookie и User-Agent.

Так за Cloudflare работают и вход на трекер, и скачивание `.torrent`-файлов —
с FlareSolverr и с Byparr (проверено на kinozal.me с обоими). При следующих запусках
используется сохранённая cookie, решатель не вызывается, пока она действует.

### Требование: один IP-адрес

Решатель должен выходить к трекеру с того же IP-адреса, что и TorrentMonitor:
тот же хост, тот же VPN или прокси. Иначе Cloudflare не принимает cookie.
В этом случае страницы всё равно читаются через браузер решателя,
но `.torrent`-файлы скачать не удаётся.

Если для трекера в TM задан прокси, тот же прокси передаётся решателю.

Если проверку пройти не удалось, в разделе **Ошибки** появляется предупреждение:
«Трекер закрыт проверкой Cloudflare, пройти её не удалось. Проверьте в настройках
адрес FlareSolverr или Byparr.»

---

## Что выбрать

| Ситуация | Решение |
|---|---|
| Провайдер блокирует трекер | другой адрес (зеркало) трекера, прокси/TOR |
| Заблокировано несколько трекеров | глобальный прокси или TOR |
| Нужен прокси только для одного трекера | индивидуальный прокси в расширенных настройках |
| Трекер за Cloudflare («проверка браузера») | FlareSolverr/Byparr |
