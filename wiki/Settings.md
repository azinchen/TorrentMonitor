# Настройки

Справочник по разделу **Настройки** веб-интерфейса. Раздел состоит из шести блоков:
«Общие», «Torrent-клиент», «Уведомления», «Сеть», «Вход», «API и Sonarr».
У блока своя кнопка «Сохранить»; отметки в блоках «Вход» и «API и Sonarr»
сохраняются сразу.

Учётные данные трекеров, их зеркала и прокси для отдельного трекера задаются
не здесь, а в разделе [«Трекеры»](Web-Interface#трекеры).

---

## Общие

| Настройка | Описание |
|---|---|
| **Адрес TorrentMonitor** | Полный адрес TorrentMonitor с протоколом, например `http://torrent.test.ru/`. Используется в RSS-ленте и в ссылках на `.torrent`-файлы, которые получают Synology Download Station и TorrServer, — для них этот адрес должен быть доступен (см. [Торрент-клиенты](Torrent-Clients#как-торрент-файл-попадает-в-клиент)). Из него же составляется адрес webhook для Sonarr. |
| **RSS-лента скачанных torrent-файлов** | Отдавать RSS-ленту по адресу `/rss`. |
| **Устанавливать обновления TorrentMonitor автоматически** | Автоматически обновлять TorrentMonitor при выходе новой версии. В Docker обновление обычно выполняется обновлением образа — см. [Обновление](Updating). |
| **Подробный журнал проверки** | В журнал проверки пишутся все запросы к трекерам — включайте при разборе проблем. Журнал виден в «Состояние → Последняя проверка». |
| **Прекращать проверку через** | Число дней без обновлений, после которых тема больше не проверяется. `0` — проверять всегда (по умолчанию). См. [ниже](#прекращение-проверки-тем-без-обновлений). |

### Прекращение проверки тем без обновлений

Если в теме не было обновлений заданное число дней, движок перестаёт её проверять.
Дни считаются от последнего обновления темы, а если их не было — от дня,
когда тема добавлена.

- У отдельной темы может быть своё значение: поле «Прекращать проверку через»
  в дополнительных настройках темы или параметр `stopAfterDays` в
  [API](API#post-apitorrents--добавить-тему-или-сериал) (`0` — проверять всегда).
- В списке такая тема получает метку «проверка прекращена»; в API у неё поле
  `stopped` равно `true`.
- Проверить такую тему разово можно кнопкой «Проверить» в её строке или из консоли:
  `php engine.php --topic=<id>` — этот запуск проверяет тему в любом случае.

## Torrent-клиент

| Настройка | Описание |
|---|---|
| **Передавать скачанные torrent-файлы в torrent-клиент** | Включает передачу раздач в клиент. Без этого TM только складывает `.torrent`-файлы в каталог `torrents/`. |
| **Клиент** | Deluge, qBittorrent, SynologyDS, TorrServer или Transmission. |
| **Адрес клиента** | Полный адрес с протоколом, например `http://127.0.0.1:9091`. |
| **Логин / Пароль** | Учётные данные веб-интерфейса клиента (у Deluge — только пароль). Сохранённый пароль в браузер не передаётся: пустое поле означает «не менять». Отметка «Удалить сохранённый пароль» стирает его. |
| **Каталог загрузки** | Куда клиент сохраняет файлы, например `/var/lib/transmission/downloads` или `C:/downloads`. Путь указывается так, как его видит **клиент**, а не TorrentMonitor. Если оставить пустым, клиент использует собственные настройки (qBittorrent — папку по умолчанию или папку категории). У темы может быть свой каталог. |
| **Категория** | Только для qBittorrent: категория для новых раздач, у которых не задана своя. |
| **Сериалы: при выходе новой серии удалять из клиента раздачу предыдущей** | Для сериалов: при выходе новой серии прежняя раздача удаляется из клиента. У тем форумных трекеров прежняя раздача при обновлении заменяется новой всегда, независимо от этой настройки (скачанные файлы остаются). |
| **…вместе со скачанными файлами предыдущей серии** | Удалять и файлы прежней раздачи сериала. Работает только для lostfilm.tv, baibako.tv и newstudio.tv. |
| **При удалении темы вместе с раздачей по умолчанию удалять и скачанные файлы** | Задаёт начальное состояние отметки «…вместе со скачанными файлами» в окне удаления темы; действует и там, где спросить некого (API, Sonarr). По умолчанию выключено. Файлы удаляются в Transmission, qBittorrent и Deluge. |

Кнопка **«Сохранить и проверить подключение»** сохраняет настройки и сразу пробует
войти в клиент. Ответ — «Подключение к … работает.» или текст ошибки.

Подробности по каждому клиенту — на странице [Торрент-клиенты](Torrent-Clients).

## Уведомления

| Настройка | Описание |
|---|---|
| **Отправлять уведомления** | Общий выключатель. |
| **Об обновлениях раздач и новых версиях** | Сообщения о новых сериях, обновлённых раздачах и новых версиях TorrentMonitor: сервис и адрес. |
| **Об ошибках** | Сообщения об ошибках (не удалось войти на трекер и т.п.): сервис и адрес могут быть другими. |
| **Сервис** | E-mail, Prowl, Pushbullet, Pushover, Pushall, Telegram или Gotify. |
| **Адрес или ключи** | Формат зависит от сервиса; подсказка показана под полем. |

Кнопка **«Отправить пробное сообщение»** отправляет сообщение по тому, что сейчас
введено в полях.

Форматы адресов для каждого сервиса — на странице [Уведомления](Notifications).

## Сеть

| Настройка | Описание |
|---|---|
| **Решатель Cloudflare** | Адрес [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr) или [Byparr](https://github.com/ThePhaseless/Byparr) для прохождения проверки Cloudflare, например `http://byparr:8191`. Пустое поле — не используется. Подробно — на странице [Прокси и зеркала](Proxy-and-Mirrors#cloudflare-flaresolverr-и-byparr). |
| **Обращаться к трекерам через прокси** | Включает общий прокси для запросов к трекерам. |
| **Адрес прокси** | Например `127.0.0.1:9050`. |
| **Тип прокси** | SOCKS5 или HTTP. |
| **Время ожидания ответа** | Секунд на один запрос к трекеру, по умолчанию 15. Увеличьте, если трекеры отвечают медленно (например, через TOR). |
| **User-Agent** | Так TorrentMonitor представляется трекерам. Обычно достаточно значения по умолчанию; менять имеет смысл, если трекер начал отклонять запросы. |

Прокси для отдельного трекера задаётся в разделе «Трекеры» —
см. [Прокси и зеркала](Proxy-and-Mirrors#прокси-только-для-одного-трекера).

## Вход

| Настройка | Описание |
|---|---|
| **Защищать интерфейс паролем** | Требовать пароль для входа в веб-интерфейс. Сохраняется сразу. Отключайте, только если TM недоступен никому, кроме вас. |
| **Сменить пароль** | Текущий пароль, новый пароль (не короче 4 символов) и он же ещё раз. Текущий пароль не спрашивается, если защита выключена. |

- Смена пароля включает защиту паролем, если она была выключена.
- После смены пароля входы «Запомнить меня» на всех устройствах перестают действовать.
- Если установка была настроена без пароля, включить защиту можно только задав пароль:
  иначе интерфейс ответит «Сначала задайте пароль.»
- Забыли пароль — см. [Решение проблем](Troubleshooting#забыл-пароль-от-веб-интерфейса).

## API и Sonarr

Ключ API нужен для [REST API](API) и [интеграции с Sonarr](Sonarr-Integration).
Он создаётся при первоначальной настройке. На странице ключ не показан, пока вы
об этом не попросите.

- **Показать ключ** — показывает ключ и готовый адрес webhook для Sonarr.
  «Скопировать адрес webhook» кладёт адрес в буфер обмена.
- **Создать новый ключ** — заменяет ключ. **Прежний ключ перестаёт действовать**,
  его нужно заменить в Sonarr и скриптах. Если ключа ещё нет, кнопка называется
  «Создать ключ».
- **При удалении сериала в Sonarr удалять его темы и раздачи (событие On Series Delete)** —
  по умолчанию выключено. Действует для тем, добавленных через webhook Sonarr, —
  см. [Интеграция с Sonarr](Sonarr-Integration#удаление-сериала-в-sonarr).

Ключ передаётся в заголовке `Authorization: Bearer КЛЮЧ` или в параметре `?token=`.
Полный справочник — на странице [API](API).
