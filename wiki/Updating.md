# Обновление

Трекеры регулярно меняют вёрстку и домены, поэтому обновляться стоит своевременно —
исправления модулей трекеров выходят с каждой версией
(список версий и изменений — на странице [Releases](https://github.com/azinchen/TorrentMonitor/releases)).

TorrentMonitor сам проверяет эту страницу (не чаще раза в 6 часов). О новой версии
сообщает строка «Доступна версия …» вверху интерфейса; в разделе **Состояние**
показаны описание изменений и кнопка «Установить». Проверить сразу можно ссылкой
«Проверить обновления TorrentMonitor» внизу раздела «Состояние».

---

## Резервное копирование

Перед любым обновлением сохраните **каталог данных** (по умолчанию `data/` в каталоге
TorrentMonitor, либо каталог из `TM_DATA_DIR`; в Docker — том `db`): в нём все темы,
учётные данные и настройки. Рядом с `config.json` и `torrents.json` TorrentMonitor сам хранит
предыдущую версию каждого файла (`*.bak`).

## Обновление в Docker

Обновите образ и пересоздайте контейнер (`docker compose pull && docker compose up -d`
или средствами вашего NAS). Данные сохраняются в томах — при правильно настроенных
томах обновление безопасно. Подробная инструкция — в вики Docker-проекта:
[Updating-and-Maintenance](https://github.com/alfonder/torrentmonitor-dockerized/wiki/Updating-and-Maintenance).

При переходе с 3.x на 4.0 в Docker ничего делать вручную не нужно: тома остаются прежними,
корень сайта в образе уже настроен, а данные из базы контейнер переносит сам при первом
запуске — см. [Установка в Docker](Installation-Docker#обновление-с-версии-3x).

## Автоматическое обновление (LAMP)

В **Настройки → Общие** есть отметка «Устанавливать обновления TorrentMonitor
автоматически» — TorrentMonitor сам скачивает архив новой версии со страницы
Releases и распаковывает его поверх установленных файлов. То же самое делает
кнопка **«Установить»** в разделе «Состояние» — один раз, по вашей команде. Файл `config.php`, каталог данных
`data/`, каталоги `torrents/` и `scripts/` при этом не изменяются. Файлы и каталоги
прежних версий, которые больше не используются, обновление удаляет само.

Для этого нужны расширение PHP `zip` и права на запись во все файлы приложения
для пользователя, от имени которого запускается `engine.php` (и веб-сервера,
если обновление запускается из интерфейса). Выполнены ли эти условия, показывает
«Состояние → Проверка работы».

> В Docker этот механизм не используется — версия приложения фиксируется образом,
> обновляйтесь через `docker pull`.

## Ручное обновление (LAMP)

1. Сделайте резервную копию каталога данных и `config.php` (если он есть).
2. Скачайте архив новой версии со страницы [Releases](https://github.com/azinchen/TorrentMonitor/releases) и распакуйте поверх старой
   (или в новый каталог, перенеся `config.php`, каталог данных, каталоги `torrents/`
   и `scripts/`).
3. Проверьте права: `chown -R www-data:www-data /var/www/torrentmonitor`.
4. Откройте веб-интерфейс и убедитесь, что номер версии внизу меню изменился.

## Переход с версии 3.x на 4.0

В версии 4.0 переписано ядро программы. Шаги ниже — для установки в LAMP; в Docker их
выполняет образ (см. [Обновление в Docker](#обновление-в-docker)). При обновлении с 3.x:

1. Сделайте резервную копию каталога данных и `config.php`.
2. Замените файлы программы новыми. Сохраните `config.php`, `data/`, `torrents/`
   и `scripts/`.
3. Если прежняя версия хранила данные в базе, выполните `php tools/convert-db.php` —
   см. [Переход с версии с базой данных](#переход-с-версии-с-базой-данных).
4. **Измените корень сайта на каталог `public/`** — см. ниже.
5. Откройте веб-интерфейс и проверьте темы и настройки. Интерфейс выглядит иначе —
   см. [ниже](#новый-веб-интерфейс).

Строка cron не меняется: `php /var/www/torrentmonitor/engine.php`.

### Новый веб-интерфейс

Веб-интерфейс переписан. Подробное описание — на странице [Веб-интерфейс](Web-Interface).

- **Пароль остаётся прежним.** Форма первоначальной настройки после переноса не
  показывается: сразу спрашивается пароль. Хеш пароля в старом формате заменяется
  новым при первом входе. Пароля по умолчанию `torrentmonitor` больше нет.
- Интерфейс — одна страница с пятью разделами: «Торренты», «Пользователи»,
  «Трекеры», «Настройки», «Состояние».
- Где теперь прежние страницы:

  | Было | Стало |
  |---|---|
  | «Учётные данные» | раздел «Трекеры» |
  | «Ошибки», «Тестирование», «Запуск», «Новости» | раздел «Состояние» |
  | кнопка «Добавить» с вкладками | кнопки «Добавить тему» и «Добавить сериал» в разделе «Торренты»; пользователи — в разделе «Пользователи» |
  | вкладки настроек | блоки «Общие», «Torrent-клиент», «Уведомления», «Сеть», «Вход», «API и Sonarr» — см. [Настройки](Settings) |
  | «Прокси для отдельных трекеров» (текст в формате JSON) | поле «Прокси» в форме трекера |

- Ключ API на странице не показан, пока вы не нажмёте «Показать ключ»
  в **Настройки → API и Sonarr**. Прежний ключ продолжает действовать.
- Оформление — светлое или тёмное, по умолчанию как в системе.
- Страница не загружает файлы с других сайтов.
- Адреса `/action.php` и `/include/*.php` больше не существуют. Если ими
  пользовались ваши скрипты, перейдите на [REST API](API).

### Корень сайта — каталог public/

Корнем сайта теперь должен быть каталог `public/` внутри каталога TorrentMonitor.
Программа, `config.php`, `data/`, `torrents/` и `src/` лежат выше него и из браузера
недоступны. Адреса `/`, `/api/...`, `/rss` и `/torrents/<файл>.torrent` работают
как прежде. Адресов `/action.php` и `/include/*.php` больше нет.

**nginx** — измените `root` и `location /`:

```nginx
root /var/www/torrentmonitor/public;
index index.php;

location / {
    try_files $uri /index.php$is_args$args;
}
```

Блок `location ~ \.php$` остаётся прежним. Правило `location ^~ /data/ { deny all; }`
больше не нужно. Пока `root` указывает на каталог программы, вместо интерфейса
открывается страница «Нужно изменить корень сайта» с инструкцией.

**Apache** — укажите `DocumentRoot /var/www/torrentmonitor/public` и разрешите
`.htaccess` (`AllowOverride All`). Файл `public/.htaccess` направляет все запросы
в `index.php`; нужен `mod_rewrite`, без него используется `FallbackResource`.
Если оставить `DocumentRoot` на каталоге программы, то при включённом `mod_rewrite`
`.htaccess` в каталоге программы сам передаёт запросы в `public/`.

Полные примеры — на странице [Установка в LAMP](Installation-LAMP#шаг-5--настроить-веб-сервер).

### Что можно удалить

В каталоге программы больше не используются каталоги `class/`, `trackers/`, `include/`,
`pages/`, `api/`, `rss/`, `assets/`, `img/` и файл `action.php`. Их можно удалить.
Встроенное обновление при следующих обновлениях удаляет их само.

### config.php

- Строка `include_once dirname(__FILE__).'/class/Config.class.php';` больше не нужна.
  Если она осталась, это ничему не мешает.
- Новые необязательные настройки (примеры — в `config.php.example`):
  `torrents.dir` — каталог для скачанных `.torrent`-файлов;
  `connectivity.url` — адрес проверки подключения к интернету перед опросом
  трекеров (пустая строка отключает проверку).

### Что ещё изменилось

- Файлы `torrents.json` и `state.json` получили новый формат (версия 2). Файлы
  прежнего формата преобразуются сами при первом запуске — см. ниже.
- Имена полей в [REST API](API) изменились. Внешние программы, которые читают API,
  нужно поправить — см. [таблицу соответствия](API#изменения-в-версии-40).
- Трекеры casstudio.tk, hamsterstudio.org и tfile.cc удалены: этих сайтов больше не существует.
  Темы этих трекеров остаются в списке с предупреждением
  «Трекер больше не поддерживается.»
- qBittorrent, Transmission и Deluge получают `.torrent`-файл напрямую и больше
  не обращаются к адресу TorrentMonitor — см. [Торрент-клиенты](Torrent-Clients).
- Webhook Sonarr работает иначе — см. [Интеграция с Sonarr](Sonarr-Integration).

## Формат файлов данных

В каждом файле данных записан номер формата (`version`). Если новая версия
TorrentMonitor меняет формат, она сама преобразует файл при первом запуске.
Предыдущая версия `config.json` и `torrents.json` остаётся рядом (`*.bak`).
В версии 4.0 формат `torrents.json` и `state.json` — 2. Файл, созданный более новой версией, старая
версия не откроет и сообщит об этом — данные она не испортит.

## Переход с версии с базой данных

Версии 3.x хранили данные в SQLite, MySQL или PostgreSQL. Данные переносятся
один раз отдельной программой `tools/convert-db.php`; сам TorrentMonitor с базой
данных больше не работает и до переноса показывает сообщение с этой командой.

> В Docker эту программу запускает сам контейнер при первом запуске версии 4.0 —
> см. [Установка в Docker](Installation-Docker#обновление-с-версии-3x).

1. Сделайте резервную копию базы.
2. Обновите файлы TorrentMonitor, **не удаляя** прежние `config.php` и `config.xml`.
3. Проверьте, что будет перенесено, ничего не записывая:

   ```bash
   cd /var/www/torrentmonitor
   php tools/convert-db.php --dry-run
   ```

4. Перенесите данные (от имени пользователя веб-сервера, чтобы файлы достались ему):

   ```bash
   sudo -u www-data php tools/convert-db.php
   ```

5. Откройте веб-интерфейс и проверьте темы и настройки. После этого строки `db.*`
   и `encryption.key` в `config.php` и файл `config.xml` больше не нужны.

Что нужно знать:

- Настройки подключения и ключ шифрования программа берёт из прежнего `config.php`.
  Их можно задать и параметрами: `--type`, `--db`, `--host`, `--port`, `--user`,
  `--password`, `--key`, `--key-file`; каталог данных — `--data`. Полный список:
  `php tools/convert-db.php --help`.
- Нужен PDO-драйвер прежней базы (`php-sqlite3`, `php-mysql` или `php-pgsql`) —
  только на время переноса.
- База только читается и остаётся как была.
- Пароли, зашифрованные прежним ключом, расшифровываются и записываются в открытом
  виде. Если ключа нет, программа перечислит, что придётся ввести заново.
- Прокси для отдельных трекеров переносятся из `config.xml`.
- Уже существующие файлы данных не заменяются без `--force`.

## Откат

- **Docker**: укажите предыдущий тег образа (`alfonder/torrentmonitor:vX.X.X-N`)
  и восстановите каталог данных из копии, если формат файлов успел обновиться.
  Вернуться с 4.0 на образ с версией 3.x можно, только пока в томе `db` лежат прежние
  файлы (`tm.sqlite`, `config.xml`, `db_crypt.key`); изменения, сделанные в 4.0,
  в прежнюю базу не записываются.
- **LAMP**: разверните предыдущую версию файлов и восстановите каталог данных из копии.
