# Обновление

Трекеры регулярно меняют вёрстку и домены, поэтому обновляться стоит своевременно —
исправления модулей трекеров выходят с каждой версией
(список версий и изменений — на странице [Releases](https://github.com/azinchen/TorrentMonitor/releases)).

TorrentMonitor сам проверяет эту страницу (не чаще раза в 6 часов). Проверка, запущенная
кнопкой «Проверить сейчас», спрашивает о новой версии сразу и, если включена автоматическая
установка, устанавливает её, не дожидаясь этих шести часов. О новой версии
сообщает строка «Доступна версия …» вверху интерфейса; в разделе **Состояние**
показаны описание изменений и кнопка «Установить». Проверить сразу можно ссылкой
«Проверить обновления TorrentMonitor» внизу раздела «Состояние».

---

## Резервное копирование

Перед любым обновлением сохраните **каталог данных** (по умолчанию `data/` в каталоге
TorrentMonitor, либо каталог из `TM_DATA_DIR`; в Docker — том `db`): в нём все темы,
учётные данные и настройки. Рядом с `config.json` и `torrents.json` TorrentMonitor сам хранит
предыдущую версию каждого файла (`*.bak`).

## Обновление в Docker

Обновите образ и пересоздайте контейнер (`docker compose pull && docker compose up -d`
или средствами вашего NAS). Данные сохраняются в томах — при правильно настроенных
томах обновление безопасно. Подробная инструкция — в вики Docker-проекта:
[Updating-and-Maintenance](https://github.com/alfonder/torrentmonitor-dockerized/wiki/Updating-and-Maintenance).

Переходите с версии 3.x? См. [Переход с версии 3.x](#переход-с-версии-3x).

## Автоматическое обновление (LAMP)

В **Настройки → Общие** есть отметка «Устанавливать обновления TorrentMonitor
автоматически» — TorrentMonitor сам скачивает архив новой версии со страницы
Releases и распаковывает его поверх установленных файлов. То же самое делает
кнопка **«Установить»** в разделе «Состояние» — один раз, по вашей команде. Файл `config.php`, каталог данных
`data/`, каталоги `torrents/` и `scripts/` при этом не изменяются. Файлы и каталоги
программы, которые больше не используются, обновление удаляет само.

### Какие версии устанавливаются

Когда автоматическая установка включена, под отметкой появляется выбор «Какие версии»:

| Выбор | Что устанавливается |
|---|---|
| **Стабильные версии** (по умолчанию) | последний обычный выпуск |
| **Бета-версии** | самая новая версия — бета или стабильная, какая вышла позже |
| **Версия в разработке** | текущее состояние репозитория, после каждого изменения в нём. Номер версии показан вместе с меткой изменения: `4.0.0 (dev 72dfdcf)` |

- Без автоматической установки TorrentMonitor сообщает только о стабильных версиях.
- **При смене выбора** устанавливается последняя версия нового выбора, даже если она ниже
  установленной: например, после перехода с версии в разработке на бета-версии ставится
  последняя бета. Настройки об этом предупреждают при сохранении, а в разделе «Состояние»
  вместо «Доступна версия» написано «Будет установлена версия». Данные при этом остаются
  как есть — см. [Формат файлов данных](#формат-файлов-данных).
- В остальное время устанавливается только более новая версия.
- Ниже версии 4.0.0-beta2 смена выбора не опускает: более ранние версии не читают
  нынешние файлы данных.
- Версия, вышедшая раньше этого выбора, знает только стабильные версии: после возврата
  на неё она сама обновится до следующего стабильного выпуска.

Для обновления нужны расширение PHP `zip` и права на запись во все файлы приложения
для пользователя, от имени которого запускается `engine.php` (и веб-сервера,
если обновление запускается из интерфейса). Выполнены ли эти условия, показывает
«Состояние → Проверка работы».

> В Docker встроенное обновление тоже работает, но только до пересоздания контейнера:
> файлы программы берутся из образа, поэтому после `docker compose up` с тем же образом
> возвращается версия образа (данные в томах остаются). Надёжный способ обновления
> в Docker — новый образ (`docker pull`).

## Ручное обновление (LAMP)

1. Сделайте резервную копию каталога данных и `config.php` (если он есть).
2. Скачайте архив новой версии со страницы [Releases](https://github.com/azinchen/TorrentMonitor/releases) и распакуйте поверх старой
   (или в новый каталог, перенеся `config.php`, каталог данных, каталоги `torrents/`
   и `scripts/`).
3. Проверьте права: `chown -R www-data:www-data /var/www/torrentmonitor`.
4. Откройте веб-интерфейс и убедитесь, что номер версии внизу меню изменился.

## Переход с версии 3.x

Версии 3.x хранили данные в базе (SQLite, MySQL или PostgreSQL) и открывались из каталога
программы. Теперь данные лежат в файлах, а корень сайта — каталог `public/`. Перейти
с 3.x можно только через перенос данных, описанный здесь.

**С каких версий можно перейти.** Переносятся базы версии **2.0 и новее** (2.0 вышла
в феврале 2023 года), включая все версии 3.x. Обновляться до 3.x перед этим не нужно. Важна
версия именно базы, а не программы: в Docker новый образ обновлял программу, но не базу,
поэтому база там может быть старше программы — это тоже учтено. Перенос сообщает, какую
версию базы он нашёл. База старше 2.0 тоже будет перенесена, но с предупреждением: такие
базы не проверялись.

В отчёте переноса, в разделе «Замечания», указано:

- трекеры, которые с тех пор переименованы (`rutor.info` → `rutor.is`, `nnm-club.me` →
  `nnmclub.to`): их темы и учётные записи перенесены под нынешним названием;
- темы трекеров, с которыми версия 4 не работает (`tfile.cc`, `baibako.tv`, `casstudio.tk`,
  `hamsterstudio.org`): они перенесены, но проверяться не будут — удалите их в интерфейсе.

**Docker.** Вручную ничего делать не нужно: обновите образ и пересоздайте контейнер.
Тома остаются прежними, корень сайта в образе уже настроен, данные из базы контейнер
переносит сам при первом запуске — см.
[Установка в Docker](Installation-Docker#обновление-с-версии-3x).

**LAMP:**

1. Сделайте резервную копию базы, каталога программы и `config.php`.
2. Замените файлы программы новыми, **не удаляя** прежние `config.php` и `config.xml`.
   Сохраните также `torrents/` и `scripts/`.
3. Перенесите данные из базы — см. [ниже](#перенос-данных-из-базы).
4. Измените корень сайта на каталог `public/` — см. [ниже](#корень-сайта--каталог-public).
5. Откройте веб-интерфейс и проверьте темы и настройки.

Строка cron не меняется: `php /var/www/torrentmonitor/engine.php`.

Пароль веб-интерфейса остаётся прежним; форма первоначальной настройки после переноса
не показывается. Ключ API тоже сохраняется.

Каталоги `class/`, `trackers/`, `include/`, `pages/`, `api/`, `rss/`, `assets/`, `img/`
и файл `action.php` в каталоге программы после перехода не используются: их можно
удалить, встроенное обновление удаляет их само. Строки `db.*` и `encryption.key`
в `config.php` и файл `config.xml` после переноса данных тоже не нужны.

### Перенос данных из базы

Данные переносятся один раз программой `tools/convert-db.php`. Пока перенос не сделан,
TorrentMonitor вместо интерфейса показывает сообщение с этой командой.

1. Проверьте, что будет перенесено, ничего не записывая:

   ```bash
   cd /var/www/torrentmonitor
   php tools/convert-db.php --dry-run
   ```

2. Перенесите данные (от имени пользователя веб-сервера, чтобы файлы достались ему):

   ```bash
   sudo -u www-data php tools/convert-db.php
   ```

Что нужно знать:

- Настройки подключения и ключ шифрования программа берёт из прежнего `config.php`.
  Их можно задать и параметрами: `--type`, `--db`, `--host`, `--port`, `--user`,
  `--password`, `--key`, `--key-file`; каталог данных — `--data`. Полный список:
  `php tools/convert-db.php --help`.
- Нужен PDO-драйвер прежней базы (`php-sqlite3`, `php-mysql` или `php-pgsql`) —
  только на время переноса.
- База только читается и остаётся как была.
- Пароли, зашифрованные прежним ключом, расшифровываются и записываются в открытом
  виде. Если ключа нет, программа перечислит, что придётся ввести заново.
- Прокси для отдельных трекеров переносятся из `config.xml`.
- Уже существующие файлы данных не заменяются без `--force`.

### Корень сайта — каталог public/

Корнем сайта должен быть каталог `public/` внутри каталога TorrentMonitor.
Программа, `config.php`, `data/`, `torrents/` и `src/` лежат выше него и из браузера
недоступны.

**nginx** — измените `root` и `location /`:

```nginx
root /var/www/torrentmonitor/public;
index index.php;

location / {
    try_files $uri /index.php$is_args$args;
}
```

Блок `location ~ \.php$` остаётся как был. Пока `root` указывает на каталог программы,
вместо интерфейса открывается страница «Нужно изменить корень сайта» с инструкцией.

**Apache** — укажите `DocumentRoot /var/www/torrentmonitor/public` и разрешите
`.htaccess` (`AllowOverride All`). Файл `public/.htaccess` направляет все запросы
в `index.php`; нужен `mod_rewrite`, без него используется `FallbackResource`.
Если оставить `DocumentRoot` на каталоге программы, то при включённом `mod_rewrite`
`.htaccess` в каталоге программы сам передаёт запросы в `public/`.

Полные примеры — на странице [Установка в LAMP](Installation-LAMP#шаг-5--настроить-веб-сервер).

## Формат файлов данных

Файлы данных подходят любой версии TorrentMonitor. Более новая версия только добавляет
в них разделы и поля; более старая версия работает с тем, что знает, а остальное
сохраняет без изменений. Поэтому после возврата на предыдущую версию программа продолжает
работать с теми же файлами.

В каждом файле записаны номер формата (`version`) и самый старый формат, которым файл
ещё можно читать (`compatible`). Файл более старого формата программа сама преобразует
при первом запуске; предыдущая версия `config.json` и `torrents.json` остаётся рядом
(`*.bak`). Отказ открыть файл («создан более новой версией TorrentMonitor и этой версией
не читается») возможен, только если формат когда-нибудь изменится несовместимо.

## Откат

- **Docker**: укажите предыдущий тег образа (`alfonder/torrentmonitor:vX.X.X-N`).
  Файлы данных остаются как есть.
  Вернуться на образ с версией 3.x можно, только пока в томе `db` лежат прежние
  файлы (`tm.sqlite`, `config.xml`, `db_crypt.key`); изменения, сделанные после
  перехода, в прежнюю базу не записываются.
- **LAMP**: разверните предыдущую версию файлов программы. Файлы данных остаются как есть.
