# API

У TorrentMonitor есть REST API для внешних приложений:
добавление, получение списка и удаление отслеживаемых раздач, запуск проверки,
просмотр ошибок, а также webhook для [интеграции с Sonarr](Sonarr-Integration).

---

## Получение API-ключа

Ключ создаётся при первоначальной настройке TorrentMonitor.

1. Откройте **Настройки → API и Sonarr**.
2. Нажмите **«Показать ключ»**. Пока вы этого не сделали, ключ на странице не показан.
   Если ключа ещё нет, нажмите **«Создать ключ»**.

Там же показан готовый адрес webhook для Sonarr.

> ⚠️ «Создать новый ключ» заменяет ключ: прежний перестаёт действовать, и все
> клиенты API (в том числе webhook в Sonarr) нужно будет обновить.

## Авторизация

Каждый запрос должен содержать ключ одним из способов:

- заголовок `Authorization: Bearer ВАШ_КЛЮЧ` (рекомендуется);
- параметр строки запроса `?token=ВАШ_КЛЮЧ` (удобно для webhook).

Без действительного ключа API отвечает `401` с сообщением `Неверный токен.`

## Формат ответов

Все ответы — JSON:

```json
{ "ok": true,  "message": "Тема добавлена.", "data": { } }
{ "ok": false, "message": "Описание ошибки." }
```

| Код | Значение |
|---|---|
| 200 | успех |
| 201 | объект создан |
| 202 | запрос принят, выполняется в фоне |
| 401 | неверный или отсутствующий токен |
| 404 | ресурс/объект не найден |
| 409 | конфликт — тема или сериал уже отслеживается |
| 422 | неверные параметры запроса |
| 500 | проверку не удалось запустить (`POST /api/run`) |
| 503 | TorrentMonitor не может начать работу: файл данных повреждён или данные прежней версии не перенесены |

## Объект темы

`GET /api/torrents` и `GET /api/torrents/{id}` возвращают темы в одном виде:

| Поле | Тип | Описание |
|---|---|---|
| `id` | число | идентификатор темы в TorrentMonitor |
| `tracker` | строка | трекер, например `rutracker.org` |
| `name` | строка | название |
| `topicId` | строка | номер темы на трекере; у сериалов пусто |
| `url` | строка | адрес темы на трекере; у сериалов пусто |
| `quality` | строка | качество сериала: `sd`, `720` или `1080` |
| `episode` | строка | последняя серия, например `S01E02` |
| `updatedAt` | строка | дата раздачи на трекере |
| `autoRename` | true/false | брать название с трекера |
| `path` | строка | директория для скачивания; пусто — из настроек |
| `category` | строка | категория; пусто — из настроек |
| `script` | строка | скрипт, запускаемый после обновления |
| `hash` | строка | хеш раздачи темы в торрент-клиенте |
| `paused` | true/false | наблюдение приостановлено |
| `error` | true/false | при последней проверке была ошибка |
| `closed` | true/false | раздача закрыта |
| `stopAfterDays` | число или null | через сколько дней без обновлений прекращать проверку; `null` — как в настройках, `0` — проверять всегда |
| `sonarrTitle` | строка | название сериала в Sonarr, с которым связана тема; пусто — связи нет |
| `sonarrSeasons` | массив чисел | номера сезонов сериала, которые раздаются в теме |
| `addedAt` | строка | когда тема добавлена |
| `lastActivityAt` | строка | когда тема обновлялась в последний раз; пусто, если не обновлялась |
| `stopped` | true/false | проверка прекращена: тема давно не обновлялась (см. [Настройки](Settings#прекращение-проверки-тем-без-обновлений)) |

## GET /api/torrents — список тем

Параметры (необязательные): `tracker` — фильтр по трекеру.

```bash
curl -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  "http://ВАШ_АДРЕС_ТМ/api/torrents?tracker=rutracker.org"
```

Ответ:

```json
{
  "ok": true,
  "message": "1 тем.",
  "data": [
    {
      "id": 15,
      "tracker": "rutracker.org",
      "name": "Название раздачи",
      "topicId": "4201572",
      "url": "https://rutracker.org/forum/viewtopic.php?t=4201572",
      "quality": "sd",
      "episode": "",
      "updatedAt": "2026-07-01 12:00:00",
      "autoRename": true,
      "path": "",
      "category": "",
      "script": "",
      "hash": "",
      "paused": false,
      "error": false,
      "closed": false,
      "stopAfterDays": null,
      "addedAt": "2026-06-01 10:00:00",
      "lastActivityAt": "2026-07-01 12:10:00",
      "stopped": false,
      "sonarrTitle": "",
      "sonarrSeasons": []
    }
  ]
}
```

## GET /api/torrents/{id} — одна тема

`{id}` — идентификатор из `GET /api/torrents`.

```bash
curl -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  "http://ВАШ_АДРЕС_ТМ/api/torrents/15"
```

Ответ — `"message": "OK"` и один [объект темы](#объект-темы) в `data`.

Если темы с таким `{id}` нет — `404`:

```json
{ "ok": false, "message": "Тема не найдена." }
```

## POST /api/torrents — добавить тему или сериал

Тело запроса — JSON (`Content-Type: application/json`) или обычная форма.

### Вариант 1: форумный трекер (по ссылке на тему)

| Параметр | Обязателен | Описание |
|---|---|---|
| `url` | да | ссылка на тему, например `https://rutracker.org/forum/viewtopic.php?t=4201572`. Принимаются и ссылки с [зеркал](Proxy-and-Mirrors#другой-адрес-трекера-зеркало) |
| `name` | нет | своё название |
| `path` | нет | директория для скачивания (если пусто — берётся из глобальных настроек) |
| `category` | нет | категория qBittorrent (если пусто — категория по умолчанию из настроек) |
| `stopAfterDays` | нет | через сколько дней без обновлений прекращать проверку этой темы; `0` — проверять всегда. Если не указан — как в настройках |
| `sonarrTitle` | нет | название сериала в Sonarr или адрес его страницы в Sonarr: связывает тему с сериалом — см. [Интеграция с Sonarr](Sonarr-Integration#связь-своей-темы-с-сериалом) |
| `sonarrSeasons` | с `sonarrTitle` — да | номера сезонов: массив `[2]` или строка `"1, 2"` |

```bash
curl -X POST "http://ВАШ_АДРЕС_ТМ/api/torrents" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://rutracker.org/forum/viewtopic.php?t=4201572","name":"Название (необязательно)"}'
```

Успех — `201`:

```json
{ "ok": true, "message": "Тема добавлена.", "data": { "id": 15, "tracker": "rutracker.org", "topicId": "4201572" } }
```

Требования: URL должен принадлежать поддерживаемому форумному трекеру, и для этого
трекера в разделе **Трекеры** должны быть заполнены учётные данные (если они ему нужны). Ссылки
lostfilm.tv и newstudio.tv не принимаются — это RSS-трекеры, используйте вариант 2.

Ошибки:

| Код | Сообщение |
|---|---|
| 422 | `Не удалось разобрать URL или трекер не поддерживается.` |
| 422 | `Нет учётных данных для трекера: rutracker.org.` |
| 409 | `Тема уже отслеживается.` |

### Вариант 2: RSS-трекер (сериал по названию)

| Параметр | Обязателен | Описание |
|---|---|---|
| `tracker` | да | `lostfilm.tv`, `lostfilm-mirror` или `newstudio.tv` |
| `name` | да | название сериала на английском, например `House` |
| `quality` | нет | качество: `sd` (по умолчанию), `720` или `1080` |
| `path` | нет | директория для скачивания (если пусто — берётся из глобальных настроек) |
| `category` | нет | категория qBittorrent (если пусто — категория по умолчанию из настроек) |
| `stopAfterDays` | нет | как в варианте 1 |

```bash
curl -X POST "http://ВАШ_АДРЕС_ТМ/api/torrents" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"tracker":"lostfilm.tv","name":"House","quality":"1080"}'
```

Успех — `201`:

```json
{ "ok": true, "message": "Сериал добавлен.", "data": { "id": 16, "tracker": "lostfilm.tv", "name": "House", "quality": "1080" } }
```

Числовой параметр `hd` тоже принимается, если `quality` не указан:
`0` = SD, `1` = 720p, `2` = 1080p. У lostfilm.tv и lostfilm-mirror значения `hd`
другие: `1` = 1080, `2` = 720
(см. [трекеры](Supported-Trackers#выбор-качества-у-rss-трекеров)).

Ошибки:

| Код | Сообщение |
|---|---|
| 422 | `Укажите url (тема форумного трекера) или tracker + name (сериал).` |
| 422 | `Трекер rutracker.org не отслеживает сериалы по названию. Используйте параметр url.` |
| 422 | `Нет учётных данных для трекера: lostfilm.tv.` |
| 422 | `Недопустимое название сериала.` |
| 422 | `Параметр quality должен быть sd, 720 или 1080.` |
| 422 | `Параметр hd должен быть 0, 1 или 2.` |
| 409 | `Сериал уже отслеживается.` |

## DELETE /api/torrents/{id} — удалить тему

`{id}` — идентификатор из `GET /api/torrents`.

```bash
curl -X DELETE "http://ВАШ_АДРЕС_ТМ/api/torrents/15" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ"
```

Необязательные параметры запроса:

| Параметр | Значение |
|---|---|
| `removeFromClient=1` | удалить раздачу также из торрент-клиента |
| `deleteData=1` / `deleteData=0` | удалять ли скачанные файлы. Если параметр не указан, действует настройка «При удалении темы вместе с раздачей по умолчанию удалять и скачанные файлы». Работает только вместе с `removeFromClient=1` |

```bash
curl -X DELETE "http://ВАШ_АДРЕС_ТМ/api/torrents/15?removeFromClient=1&deleteData=1" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ"
```

Удаление файлов поддерживают Transmission, qBittorrent и Deluge.

Успех — `200`:

```json
{ "ok": true, "message": "Тема удалена." }
```

Если раздача удалена и из клиента, сообщение —
`Тема удалена, раздача удалена из торрент-клиента.`

Ошибки: `422` `Укажите ID: DELETE /api/torrents/{id}` — не указан `{id}`;
`404` `Тема не найдена.`

## POST /api/run — запустить проверку

Запускает `engine.php` в фоне — то же, что кнопка «Проверить сейчас» в интерфейсе.
Тело запроса не обязательно. В JSON можно ограничить проверку:

| Параметр | Описание |
|---|---|
| `tracker` | проверить только темы этого трекера, например `"rutracker.org"`. Неизвестное название игнорируется |
| `topic` | проверить только тему с этим `id` (в том числе ту, проверка которой прекращена) |

```bash
curl -X POST "http://ВАШ_АДРЕС_ТМ/api/run" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ"

curl -X POST "http://ВАШ_АДРЕС_ТМ/api/run" \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"topic":15}'
```

Успех — `202`:

```json
{ "ok": true, "message": "Проверка запущена." }
```

Если проверка уже выполняется, новая не запускается — тоже `202`:

```json
{ "ok": true, "message": "Проверка уже выполняется." }
```

> Ответ приходит сразу и означает только то, что процесс запущен. Результат
> самой проверки в нём не отражён — смотрите раздел **Состояние** интерфейса
> или `GET /api/errors`.

Если в PHP отключена функция `exec` — `500`:

```json
{ "ok": false, "message": "Функция exec отключена в PHP, запустить проверку в фоне нельзя." }
```

Если не найден CLI-интерпретатор PHP — `500`:

```json
{ "ok": false, "message": "CLI-интерпретатор PHP не найден. Укажите путь в config.php: Config::write('php.cli', '/usr/bin/php8.3');" }
```

Путь к CLI-интерпретатору определяется автоматически. Если сборка нестандартная
или на сервере несколько версий PHP, путь задаётся в `config.php`:

```php
Config::write('php.cli', '/usr/bin/php8.3');
```

## GET /api/errors — список ошибок

Те же предупреждения, что показываются в «Состояние → Ошибки» веб-интерфейса.

Параметры (необязательные): `tracker` — фильтр по источнику (полю `source`).
Набор полей с фильтром и без него одинаковый.

```bash
curl -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  "http://ВАШ_АДРЕС_ТМ/api/errors"
```

Ответ:

```json
{
  "ok": true,
  "message": "1 ошибок.",
  "data": [
    {
      "time": "2026-07-01 12:00:00",
      "source": "rutracker.org",
      "code": "cant_get_forum_page",
      "message": "Не удалось получить страницу трекера.",
      "topic": 15
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `time` | время возникновения |
| `source` | источник ошибки: трекер, торрент-клиент, `api` для ошибок webhook или `system` |
| `code` | код ошибки |
| `message` | текст ошибки |
| `topic` | идентификатор темы или `null`, если ошибка не привязана к теме |


Если ошибок нет:

```json
{ "ok": true, "message": "0 ошибок.", "data": [] }
```

## GET /api/errors/{id} — ошибки одной темы

`{id}` — идентификатор **темы** из `GET /api/torrents`, а не идентификатор ошибки.

```bash
curl -H "Authorization: Bearer ВАШ_КЛЮЧ" \
  "http://ВАШ_АДРЕС_ТМ/api/errors/15"
```

Ответ — поля те же, что у `GET /api/errors`.

Если темы с таким `{id}` нет — `404`:

```json
{ "ok": false, "message": "Тема не найдена." }
```

## POST /api/sonarr — webhook для Sonarr

Принимает уведомления Sonarr. Токен обычно передаётся в URL:
`http://ВАШ_АДРЕС_ТМ/api/sonarr?token=ВАШ_КЛЮЧ`.

| Событие (`eventType`) | Ответ |
|---|---|
| `Grab` | `202` `{"ok":true,"message":"Принято."}` — тема добавляется после ответа |
| `Test` | `200` `{"ok":true,"message":"OK"}` |
| `SeriesDelete` | `200` `Удалено тем: N.` или `Событие SeriesDelete пропущено.`, если удаление не включено в настройках |
| любое другое | `200` `Событие <название> пропущено.` |

Ошибки `Grab`: `422` `Нет downloadId в запросе.`;
`422` `В настройках TorrentMonitor не включён torrent-клиент.`

Дополнительный параметр `?category=` задаёт категорию для добавляемой темы.

Как это работает и как настроить Sonarr — на странице
[Интеграция с Sonarr](Sonarr-Integration).

## Пример на PHP

```php
<?php
$apiKey = 'ВАШ_КЛЮЧ';
$tmUrl  = 'http://ВАШ_АДРЕС_ТМ';

$ch = curl_init("$tmUrl/api/torrents");
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_POST           => true,
    CURLOPT_HTTPHEADER     => ["Authorization: Bearer $apiKey", "Content-Type: application/json"],
    CURLOPT_POSTFIELDS     => json_encode([
        'url'  => 'https://rutracker.org/forum/viewtopic.php?t=4201572',
        'name' => 'Название (необязательно)',
    ]),
]);

$response = json_decode(curl_exec($ch), true);
curl_close($ch);

if ($response['ok']) {
    echo "Добавлено: {$response['data']['tracker']} / {$response['data']['topicId']}";
} else {
    echo "Ошибка: {$response['message']}";
}
```

Для RSS-трекера замените `CURLOPT_POSTFIELDS`:

```php
CURLOPT_POSTFIELDS => json_encode([
    'tracker' => 'lostfilm.tv',
    'name'    => 'House',
    'quality' => '1080',
]),
```

## Ошибки API в интерфейсе

Проблемы обработки webhook Sonarr (торрент не найден в клиенте, не найдены учётные
данные трекера и т.п.) записываются в «Состояние → Ошибки» веб-интерфейса с источником `api`.

Те же записи доступны через `GET /api/errors` — общим списком, с фильтром по
источнику (`?tracker=api`) или по конкретной теме.
