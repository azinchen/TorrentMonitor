# Интеграция с Sonarr

TorrentMonitor интегрируется с [Sonarr](https://sonarr.tv/):
Sonarr находит и берёт релиз, а TorrentMonitor автоматически ставит соответствующую
тему трекера на мониторинг и дальше сам скачивает обновления раздачи.

## Как это работает

1. Sonarr находит подходящий релиз и отдаёт его в торрент-клиент.
2. Клиент получает `.torrent` и начинает скачивание.
3. Одновременно Sonarr отправляет **On Grab**-уведомление в TorrentMonitor
   (webhook `POST /api/sonarr`).
4. TM сразу отвечает Sonarr (HTTP 202, `{"ok":true,"message":"Принято."}`),
   а работу выполняет после ответа.
5. TM берёт `downloadId` (хеш торрента) из запроса Sonarr и ждёт появления этого
   торрента в клиенте (примерно до 15 секунд).
6. Из поля **comment** торрента TM читает ссылку на тему форума-трекера
   (например, rutracker.org кладёт её туда всегда).
7. По этой ссылке TM добавляет тему на мониторинг и будет автоматически скачивать
   обновления раздачи (новые серии).

Вместе с темой сохраняются:

- **папка и категория** торрента в клиенте — обновлённые версии раздачи попадут
  в ту же папку и категорию;
- **хеш** торрента Sonarr — при первой проверке TM не добавляет этот же торрент
  повторно, а когда выйдет новая версия, заменит старый торрент новым.

Таким образом Sonarr отвечает за выбор релиза, а TorrentMonitor — за его
дальнейшее сопровождение. Сам TorrentMonitor к Sonarr никогда не подключается.

## Требования

- TorrentMonitor настроен и работает.
- В настройках TM включён торрент-клиент **qBittorrent**, **Transmission** или **Deluge**
  с корректным адресом и паролем (см. [Торрент-клиенты](Torrent-Clients)).
  С Synology Download Station и TorrServer интеграция не работает.
- Sonarr использует **тот же клиент** в качестве Download Client.
- В разделе **Трекеры** TM заполнены учётные данные трекера, с которого скачивается торрент.
- Трекер должен быть форумным и поддерживаемым TM (rutracker.org, kinozal, nnmclub.to
  и др. — см. [список](Supported-Trackers)); ссылка на тему должна присутствовать
  в поле comment торрента.

## Шаг 1 — Взять адрес webhook в TorrentMonitor

1. Откройте **Настройки → API и Sonarr**.
2. Нажмите **«Показать ключ»**. Ключ создаётся при первоначальной настройке; если
   его ещё нет, нажмите **«Создать ключ»**.
3. Появятся ключ API и поле **«Webhook для Sonarr»** с готовым адресом вида
   `http(s)://ВАШ_АДРЕС_ТМ/api/sonarr?token=ВАШ_КЛЮЧ`. Нажмите
   **«Скопировать адрес webhook»**.

Адрес составляется из «Адреса TorrentMonitor» в **Настройки → Общие**. Проверьте,
что этот адрес открывается с того устройства, где работает Sonarr.

> «Создать новый ключ» заменяет ключ: прежний перестаёт действовать, и адрес
> webhook в Sonarr нужно обновить.

## Шаг 2 — Добавить Webhook в Sonarr

1. Откройте **Settings → Connect → + (Add Connection) → Webhook**.
2. Заполните:

   | Поле | Значение |
   |---|---|
   | Name | `TorrentMonitor` |
   | Notification Triggers | **On Grab** — обязательно; **On Series Delete** — если нужно [удаление](#удаление-сериала-в-sonarr). Остальные можно оставить включёнными: TM их принимает и пропускает |
   | URL | адрес из шага 1: `http(s)://ВАШ_АДРЕС_ТМ/api/sonarr?token=ВАШ_КЛЮЧ` |
   | Method | `POST` |

3. Нажмите **Test** — должен появиться ответ `{"ok":true,"message":"OK"}`.
4. Сохраните.

> 💡 Если Sonarr работает через прокси (**Settings → General → Proxy**), webhook тоже
> пойдёт через него и до локального адреса TM не дойдёт. Добавьте адрес TM в поле
> **Ignored Addresses** настроек прокси Sonarr. Флажка «Bypass Proxy for Local Addresses»
> недостаточно: локальными Sonarr считает только адреса без точки в имени
> и `localhost`/`127.0.0.1`, а `192.168.…` под это не подпадает.

## Категория (по желанию)

По умолчанию тема получает ту категорию, которая у торрента в клиенте
(обычно её задаёт Sonarr). Чтобы задать другую, добавьте параметр `category`
в URL webhook — он важнее категории из клиента:

```
http://ВАШ_АДРЕС_ТМ/api/sonarr?token=ВАШ_КЛЮЧ&category=sonarr
```

Если категории нет ни в URL, ни у торрента в клиенте, применяется «Категория»
из **Настройки → Torrent-клиент**
(см. [Настройки](Settings#torrent-клиент)).

## События Sonarr

| Событие | Что делает TorrentMonitor |
|---|---|
| `Grab` (On Grab) | отвечает `202` и добавляет тему на мониторинг |
| `Test` | отвечает `200`, `{"ok":true,"message":"OK"}` |
| `SeriesDelete` (On Series Delete) | удаляет темы сериала, если это включено в настройках (см. ниже); иначе пропускает |
| все остальные (On Import, On Upgrade, Rename, Health и т.д.) | принимает с `200` и пропускает |

Поэтому в Sonarr можно оставить включёнными все триггеры уведомления —
предупреждений в TM это не создаёт.

## Удаление сериала в Sonarr

**Настройки → API и Sonarr** → отметка «При удалении сериала в Sonarr удалять его
темы и раздачи (событие On Series Delete)»:

- не отмечена (по умолчанию) — событие пропускается;
- отмечена — когда сериал удаляется в Sonarr (событие On Series Delete), TM удаляет
  темы, которые были добавлены webhook для этого сериала, и убирает их раздачи
  из торрент-клиента.

Скачанные файлы: если Sonarr сообщил, что файлы сериала удалены (`deletedFiles: true`),
они удаляются и из клиента; если сообщил `deletedFiles: false` — остаются. Если Sonarr
этого поля не прислал, действует настройка «При удалении темы вместе с раздачей
по умолчанию удалять и скачанные файлы» из **Настройки → Torrent-клиент**.

Затрагиваются темы, добавленные webhook, и темы, которые вы сами связали с этим сериалом
(см. [Связь своей темы с сериалом](#связь-своей-темы-с-сериалом)). Остальные темы,
добавленные вручную, остаются.

## Замена темы при загрузке сезона целиком

Если Sonarr загрузил сезон целиком другой раздачей, прежняя тема этого сезона
обычно больше не нужна. **Настройки → API и Sonarr**:

- «Когда Sonarr загружает сезон целиком, удалять прежнюю тему этого сезона» —
  по умолчанию выключено. Прежняя тема удаляется из TM после того, как новая
  добавлена на мониторинг.
- «…и её раздачу из torrent-клиента» — появляется, когда отмечена первая настройка.
  Без неё раздача прежней темы остаётся в клиенте.

Скачанные файлы прежней раздачи удаляются, только если в **Настройки → Torrent-клиент**
отмечено «При удалении темы вместе с раздачей по умолчанию удалять и скачанные файлы».
Если прежняя и новая раздачи скачаны в одно и то же место (те же файлы), файлы
не удаляются в любом случае.

Что считается заменой:

- тот же сериал Sonarr и тот же сезон;
- новая загрузка — сезон целиком: в событии Sonarr больше одной серии, либо релиз назван
  по сезону без номера серии (`Show.S01.1080p`). Загрузка одной серии ничего не удаляет;
- прежняя тема связана с сериалом: её добавил webhook Sonarr, либо вы сами указали
  в ней сериал и сезон — см. ниже. Темы без такой связи не затрагиваются;
- если новую раздачу не удалось добавить на мониторинг, прежняя тема остаётся.

Об удалении приходит уведомление об обновлении.

## Связь своей темы с сериалом

Тему, добавленную вручную, можно связать с сериалом Sonarr — тогда она участвует в замене
и в удалении вместе с сериалом так же, как темы, добавленные webhook. В окне добавления
или изменения темы, в дополнительных настройках:

- **Сериал в Sonarr** — название сериала, как оно написано в Sonarr, либо адрес страницы
  сериала в Sonarr (`http://sonarr:8989/series/the-kitchen-2012`). Русские сериалы Sonarr
  обычно называет по-английски и нередко добавляет год: «Кухня» — `The Kitchen (2012)`,
  «Мажор» — `Silver Spoon (2014)`; русское название не подойдёт. Регистр, знаки препинания
  и лишние пробелы не важны, год в конце можно не писать. Названия сериалов, уже известных
  TM, подсказываются;
- **Сезон** — номер сезона, который раздаётся в теме (несколько — через запятую).
  Обязателен, если указан сериал.

Связь показана в строке темы: «Sonarr: название, сезон N». Чтобы убрать связь, очистите
оба поля. То же самое задаётся через [API](API): параметры `sonarrTitle` и `sonarrSeasons`.

Когда от Sonarr приходит любое событие об этом сериале, TM запоминает за темой его номер
в Sonarr и название так, как его пишет Sonarr; до первого такого события тема ждёт.

## Проверка

Возьмите в Sonarr любой релиз (Interactive Search → Grab) с трекера, для которого
в TM заполнены учётные данные. Через несколько секунд тема должна появиться
в разделе **Торренты** TorrentMonitor, а при включённых [уведомлениях](Notifications)
придёт сообщение «Тема … добавлена на мониторинг через Sonarr».

## Возможные проблемы

Webhook сразу отклоняет запрос в трёх случаях:

| Ответ | Причина и решение |
|---|---|
| `401` `Неверный токен.` | ключ в URL не совпадает с ключом в TM — возьмите адрес заново в **Настройки → API и Sonarr** и обновите URL |
| `422` `Нет downloadId в запросе.` | Sonarr отправил событие Grab без хеша торрента |
| `422` `В настройках TorrentMonitor не включён torrent-клиент.` | отметьте «Передавать скачанные torrent-файлы в torrent-клиент» в **Настройки → Torrent-клиент** |

На событие Grab TM отвечает до того, как выполнит работу, поэтому остальные проблемы
в ответе webhook не видны. Они записываются в журнал событий TM («Состояние», вид «Ошибки», источник `api`)
и доступны через `GET /api/errors`:

| Код | Сообщение | Причина и решение |
|---|---|---|
| `api_client_fail` | API: не удалось получить данные раздачи из torrent-клиента. | TM не может подключиться к клиенту, торрента с таким хешем там нет или у него пустой comment; проверьте, что TM и Sonarr используют один и тот же клиент |
| `api_bad_url` | API: поле comment торрента не содержит корректного URL. | трекер не кладёт ссылку на тему в comment или трекер не поддерживается (RSS-трекеры lostfilm/newstudio не подходят) |
| `api_no_credentials` | API: нет учётных данных для трекера в TM. | заполните этот трекер в разделе **Трекеры** |
| `api_no_download_id` | API: событие Grab не содержит downloadId. | см. таблицу выше |

Если тема уже отслеживается, это не ошибка и предупреждения нет: TM запоминает
для неё хеш торрента.

Test в Sonarr падает с ошибкой соединения — TM недоступен по указанному URL.
Если Sonarr работает через прокси, webhook уходит через него; добавьте адрес TM
в **Ignored Addresses** (см. примечание к шагу 2).
